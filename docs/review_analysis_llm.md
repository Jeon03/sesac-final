# 리뷰 분석 — LLM 활용

`crawling/pipeline_steps.py` + `market_api/services/review_analysis.py`

---

## 개요

리뷰 처리는 크롤링 파이프라인(분류)과 분석 서비스(요약·인사이트) 두 단계로 나뉜다.
GPT 호출은 총 세 곳에서 발생한다.

| 단계 | 호출 | 함수 | 역할 |
|------|------|------|------|
| 파이프라인 | 1번 | `classify_reviews()` | KeyBERT 미분류 리뷰를 카테고리로 GPT 재분류 |
| 분석 | 2번 | `_summarize_reviews()` | 긍정/부정 리뷰 그룹을 1문장으로 요약 (각각 호출) |
| 분석 | 3번 | `_generate_opportunities()` | 요약 + 불만사항 기반 시장 기회 3가지 생성 |

전체 파이프라인 흐름:

리뷰 크롤링 → 번역 (Google Translate) → KeyBERT 키워드 추출 → 1차 키워드 룰 기반 분류 → **GPT 2차 분류 (미분류만)** → DB 저장 → **GPT 리뷰 요약** → **GPT 시장 기회 생성** → ReviewAnalysisCache 저장

---

## 기술 플로우

```
리뷰 크롤링 (Ulta / Sephora / Qoo10 / Rakuten)
        ↓
번역 (Google Translate)
EN→KO / JA→EN→KO
        ↓
KeyBERT 키워드 추출 (top 5)
        ↓
1차 분류: 키워드 룰 매칭
분류 성공 → primary_category 할당
미분류    ↓
[GPT 1번 호출] classify_reviews()
키워드 + 원문 30건 배치 → GPT-4o-mini
→ v2 세분류 (보습_수분, 진정_장벽 등)
→ v1 통합 카테고리 파생 (효과_성분 등)
        ↓
ProductReview DB 저장
        ↓
[GPT 2번 호출] _summarize_reviews()
긍정(rating≥4) 리뷰 → 1문장 요약
부정(rating≤2) 리뷰 → 1문장 요약
(100건 초과 시 키워드+평점 압축 입력)
        ↓
[GPT 3번 호출] _generate_opportunities()
sentiment + 카테고리 평점 + 불만사항
+ 2번 요약 결과 (LLM 체이닝)
→ 시장 기회 3가지 JSON 생성
        ↓
ReviewAnalysisCache DB 저장
```

## 1번 호출 — GPT 2차 분류 (`classify_reviews`)

`crawling/pipeline_steps.py`

KeyBERT 키워드 룰 기반 분류에서 `미분류`로 남은 리뷰를 GPT로 재분류한다.
30건씩 배치 처리한다.

| 항목 | 내용 |
|------|------|
| 모델 | GPT-4o-mini |
| temperature | 0 |
| 출력 형식 | JSON 배열 |

**System 프롬프트**:
```
뷰티 제품 리뷰를 아래 카테고리 중 하나로 분류하세요.
카테고리: ["보습_수분", "미백_브라이트닝", "모공_각질", "주름_노화", "진정_장벽",
           "사용감_텍스처", "향_냄새", "피부_트러블_부작용", "부정_리뷰",
           "포장_배송", "가격_가성비", "고객서비스", "제품불량",
           "재구매_추천", "커버력_색상", "지속력_밀착력", "미분류"]

각 리뷰에 대해 JSON 배열로 응답하세요:
[{"idx": 번호, "primary_category": "카테고리명", "categories": ["카테고리1", ...]}]
primary_category는 가장 핵심 카테고리 1개, categories는 해당되는 카테고리 모두.
```

**User 프롬프트**:
```
[0] keywords=['dry skin', 'moisture barrier'] | text=This cream really helped my dry skin...
[1] keywords=['faint smell', 'light scent']   | text=Love the texture but the scent is a bit...
...
```

**Context**: KeyBERT 추출 키워드 + 리뷰 원문 영어 텍스트 300자 이내

**데이터 파이프라인**

KeyBERT 분류 결과 → 미분류 리뷰만 필터링 → 키워드 + 원문 조립 → 30건 배치 GPT 호출 → v2 세분류 저장 (`primary_category_v2`) → v1 통합 카테고리 파생 (`primary_category`)

**출력**:
```json
[
  {"idx": 0, "primary_category": "보습_수분", "categories": ["보습_수분", "진정_장벽"]},
  {"idx": 1, "primary_category": "향_냄새",  "categories": ["향_냄새", "사용감_텍스처"]}
]
```

> **v2 → v1 매핑**: `보습_수분`, `미백_브라이트닝`, `모공_각질`, `주름_노화`, `진정_장벽` → 모두 `효과_성분`으로 통합 (대시보드 표시용)

## 2번 호출 — 리뷰 요약 (`_summarize_reviews`)

리뷰 수에 따라 두 가지 프롬프트로 분기한다.

### 리뷰 100건 이하 — 원문 직접 입력

**System 프롬프트**: 없음

**User 프롬프트**:
```
다음은 {group} 리뷰들입니다.
- {리뷰 원문 1}
- {리뷰 원문 2}
...

규칙: 반드시 1문장. 90~110자 분량. '~입니다'로 끝내는 따뜻한 말투.
리뷰 건수·상품명·플랫폼명 언급 금지. 한국어로 작성.
```

**Context**: 리뷰 `body_ko` 필드 최대 100건, 건당 200자 이내

---

### 리뷰 100건 초과 — 키워드/카테고리 요약본 입력

리뷰 원문 대신 KeyBERT 키워드 빈도와 카테고리별 평점으로 압축해 입력한다.

**System 프롬프트**: 없음

**User 프롬프트**:
```
주요 키워드: 보습(15회), CICA(12회), 진정(10회), 향(8회), 흡수(7회), ...
카테고리 평점: 효과 / 성분 4.2점, 발림성 3.8점, 보습 / 수분 4.5점

규칙: 반드시 1문장. 90~110자 분량. '~입니다'로 끝내는 따뜻한 말투.
리뷰 건수·상품명·플랫폼명 언급 금지. 한국어로 작성.
```

**Context**:
- KeyBERT 추출 키워드 → `keyword_ko_map.json`으로 한국어 변환 → 빈도 상위 10개
- 리뷰 수 가중 카테고리 평점 상위 3개

**데이터 파이프라인**

리뷰 원문 → 평점 기준 긍정(≥4점)/부정(≤2점) 분리 → (100건 이하) 원문 직접 주입 / (100건 초과) 키워드+카테고리 압축 → GPT-4o-mini 호출 → 1문장 요약

**출력**:
```
세라마이드와 히알루론산 성분이 피부 장벽을 효과적으로 강화해 건조한 피부에 깊은 수분감을 제공합니다.
```

## 3번 호출 — 시장 기회 생성 (`_generate_opportunities`)

**System 프롬프트**: 없음

**User 프롬프트**:
```
다음은 미국 소비자 리뷰 분석 데이터입니다.

- 긍정 비율: 78% / 부정 비율: 12%
- 주요 강점: 효과 / 성분 4.3점, 발림성 4.1점, 보습 / 수분 4.5점
- 긍정 리뷰 요약: 세라마이드와 히알루론산 성분이 피부 장벽을 효과적으로 강화해...
- 부정 리뷰 요약: 일부 소비자에게 향이 강하게 느껴져 민감한 피부에는 주의가 필요합니다.
- 주요 불만사항: 피부 자극(45%), 향(32%), 가격 적절성(23%)

위 데이터를 바탕으로 한국 뷰티 브랜드가 공략할 수 있는 시장 기회 3가지를 제시해주세요.
긍정 강점 활용, 불만사항 개선, 새로운 포지셔닝 등 다양한 관점에서 분석하세요.
규칙:
- title: 4자 이내 명사형 키워드 (예: 저자극, 커버력, 향)
- description: title을 반복하지 말고, 위 데이터에서 근거를 찾아 25자 이내 인사이트 한 줄
JSON 형식으로만 응답: [{"title": "...", "description": "..."}, ...]
```

**Context**:
- 1번 호출 결과(`positive_summary`, `negative_summary`) 재사용 — LLM 체이닝
- 코드에서 계산한 sentiment 비율, 카테고리 평점 상위 3개, 불만사항 상위 3개

**데이터 파이프라인**

리뷰 데이터 집계 (sentiment, 카테고리 평점, 불만사항) + 1번 LLM 요약 결과 → 프롬프트 조립 → GPT-4o-mini 호출 → JSON 파싱 → 시장 기회 3개 반환

**출력**:
```json
[
  {"title": "저자극", "description": "향 관련 불만 45%로 무향 라인 수요 높음"},
  {"title": "보습력", "description": "세라마이드 강점 활용한 프리미엄 포지셔닝 가능"},
  {"title": "가성비", "description": "가격 불만 23%, 합리적 용량 구성으로 공략 가능"}
]
```

## 프롬프트 엔지니어링 설계 의도

**① 2단계 분류 구조**
KeyBERT 키워드 룰 기반 분류(1차) → GPT 재분류(2차, 미분류만)
→ 분류 가능한 것은 규칙으로 처리해 GPT 호출 비용 최소화

**② LLM 체이닝**
2번 호출(리뷰 요약) 결과를 3번 호출(시장 기회)의 context로 주입
→ 요약 내용을 바탕으로 일관된 시장 기회 도출

**② 리뷰 수에 따른 입력 압축**
100건 초과 시 원문 대신 키워드 빈도 + 카테고리 평점으로 압축 입력
→ 토큰 낭비 없이 핵심 정보만 전달

**③ 출력 형식 엄격 제어**
요약: 1문장, 90~110자, `~입니다` 말투 강제
기회: JSON 배열, title 4자 이내, description 25자 이내
→ UI 렌더링에 바로 사용 가능한 일관된 포맷 보장

**④ 수치 데이터 직접 주입**
sentiment 비율, 카테고리 평점, 불만사항 비중을 프롬프트에 명시
→ GPT가 수치를 지어내지 않고 실제 데이터 기반 인사이트 생성
